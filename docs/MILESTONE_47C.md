# Milestone 47C — explicit first post-third-root edge

Decision: **D237**  
Issue: **#195**

## Product boundary

47B / D236 made one third changed-basis public-34A revision root a bounded product action. 47C adds only the next already-proven construction step: one ordinary public-34B revision edge whose predecessor is that exact successful 47B root.

```text
exact successful 47B third root
+ new human post-root rationale
+ caller-explicit current third-root path
+ caller-explicit edge destination
→ one public 34B first post-third-root edge
```

This remains deliberately weaker than a third epoch:

```text
first post-third-root edge
!= root-started sequence declaration
!= third-epoch governed session
!= 40A re-entry
!= 40B restart overlay
```

## Reuse decision

No generic repeated-root-edge mechanism is introduced.

47C reuses:

- 46C / D230 as the exact second-root product analogue;
- 44D / D221 as the first-root product analogue;
- the existing public transition-root edge create/persist/load boundaries;
- the existing ordinary edge persistence format;
- the already-demonstrated 40A third-epoch construction, which requires the third 34A root followed by explicit root-started declared edge sources before declaration/re-entry;
- the exact typed `ChromiumResearchThirdChangedBasisRevisionRootResult` supplied by 47B / D236;
- the existing persisted 37C/37D versus raw 38F second-epoch launch-provenance distinction without modifying it.

The existing 40A machinery is structural prior art after this bridge exists; it does not provide the product action that creates the first post-third-root 34B edge.

**No end-to-end substitute demonstrated in this review.**

## Application authority

`persist_chromium_research_third_changed_basis_root_edge(...)` requires exactly one `ChromiumResearchThirdChangedBasisRevisionRootResult`.

Before creating the edge, it verifies that the exact 47B result remains internally coherent:

- its freshly loaded third-root SHA matches its persisted third-root SHA;
- its freshly loaded human third-root wording matches its in-memory 47B root wording.

The result retains:

- the exact 47B root result;
- the in-memory public-34B root-edge extension;
- no-overwrite persistence evidence in the existing ordinary edge format;
- one freshly loaded/relinked ordinary edge.

## Explicit locator rule

47C requires only:

1. new human post-root rationale;
2. current durable third-root source;
3. no-overwrite first-edge destination.

Only the caller-supplied current third-root file is reopened as durable predecessor evidence.

The earlier third transition, changed working set, changed working-set note, prior 37C/37D continuation overlay, or other ancestry locators are not traversed again. No path is copied or inferred from:

- the 47B root receipt;
- 47A transition/preparation receipts;
- persisted second-epoch launch provenance;
- raw 38F handoff context;
- checkpoint destinations;
- directory contents or filename conventions;
- hashes or record identities.

The root output path may be displayed as audit receipt context, but the current-root input begins blank.

## Product surface

47C is layered on the four dedicated 47B product families rather than widening every second-epoch continuation shell.

The form appears only after a newly successful exact 47B root and starts with:

- blank human rationale;
- blank current third-root source;
- blank edge destination.

A successful edge persistence:

- freshly relinks through the public 34B boundary;
- retains the exact 47B root result;
- locks the 47C form as historical evidence;
- leaves the currently mounted second-epoch controller unchanged;
- leaves the currently mounted session unchanged;
- leaves the exact current typed second-epoch continuation re-entry unchanged.

It does not expose or create a root-started sequence declaration, third-epoch governed session, third-epoch re-entry/adoption/restart, or 40B overlay.

## Historical coexistence is intentional

The exact 47B third root is durable historical relationship authority. Therefore:

```text
successful 47B third root
+ later continuation of the older second-epoch branch
→ exact third root remains eligible for its own first local 34B edge
```

The 47C edge form is not marked stale by later older-branch rollover. It remains bound to the historical exact 47B result and still requires caller-explicit current-root and destination paths.

This does not select either line as `current`, `latest`, `head`, newer, preferred, or semantically authoritative.

## Launch provenance remains orthogonal

The persisted and raw inspectable 47B products inherit the new edge action without acquiring new launch authority.

- persisted 37C/37D launches retain their exact immutable launch-location context;
- raw 38F in-process handoffs continue to have `launch_location_context=None`;
- successful 47A/47B/47C persistence does not backfill a launch path into a raw handoff;
- neither the third-root path nor the first post-root edge destination becomes launch provenance.

## Textual event ownership

The 47C product handler owns only:

`persist-research-third-changed-basis-root-edge`

It does **not** manually call its parent `on_button_pressed`. Inherited Textual handlers are dispatched through the MRO and manual redispatch can schedule inherited actions twice.

The 47C application method does explicitly invoke the inherited 47B persistence method once when extending the product workflow. Event redispatch and application workflow composition are separate concerns.

## Falsification coverage

Focused 47C tests exercise:

- exact 47B result requirement;
- valid public-34B persistence and fresh relink;
- exact retained 47B root object identity;
- no-op human rationale rejection under the existing public 34B rule;
- moved durable third-root file accepted only through an explicit current path;
- wrong root locator rejection before edge creation completes;
- existing destination preservation under no-overwrite failure;
- no edge controls before successful 47B;
- blank rationale/current-root/destination fields after 47B success;
- mounted controller/session/current typed continuation identity preserved by edge persistence;
- exact 47C edge authority surviving a later older second-epoch rollover after 47B success;
- persisted launch provenance object identity and location remaining unchanged;
- raw 38F launch provenance remaining object-identical and pathless;
- plain 47B product scope isolation;
- wrong factory authority-family rejection.

The direct deep-fixture helpers remain stem-isolated so independent no-overwrite graphs cannot collide with one another.

## Non-goals

47C does **not** add:

- a root-started third-root sequence declaration;
- a third-epoch governed session;
- third-epoch adoption, re-entry, restart, or handoff;
- a 40B overlay;
- third-epoch authority inspection;
- a new CLI flag;
- a new persistence format;
- launch-path backfill for raw handoffs;
- generic Nth-root/Nth-edge/Nth-epoch abstractions;
- a fourth evidence basis;
- arbitrary-depth ancestry;
- discovery, prefill, `current`, `latest`, `head`, chronology, or branch-ranking authority;
- path identity, authorship, authenticity, trusted-time, semantic-support, or citation authority;
- browser reacquisition or autonomous research behavior.

## Next boundary

If 47C is demonstrated, the next product question is separate: whether the exact third-root + first-edge chain should be explicitly declared/adopted into the already-existing third-epoch governed product family, or whether another product bridge is required before that handoff. 47C itself creates no declaration and grants no third-epoch launch authority.
