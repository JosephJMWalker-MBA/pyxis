# Milestone 44C — explicit first changed-basis revision-root surface

Decision: **D220**

## Purpose

44A made candidate changed evidence visible and durably preparable. 44B then exposed one explicit first 33B cross-working-set transition from exact ordinary pre-root authority.

44C productizes the next already-proven human boundary only:

```text
exact successful 44B transition
+ new human rationale
+ five explicit durable locators
→ 34A revision root
→ canonical no-overwrite persistence
→ fresh 34A relink
```

It does not create the 34B first ordinary edge after the root and does not create or adopt a 35A root-backed declared session.

## Application helper

`persist_chromium_research_first_changed_basis_revision_root(...)` consumes exactly one `ChromiumResearchFirstChangedBasisTransitionResult` and returns `ChromiumResearchFirstChangedBasisRevisionRootResult` retaining:

- exact 44B transition result;

## New human state

34A is not a mechanical conversion of 33B.

It requires the first ordinary same-working-set human revision after the changed-basis transition. Therefore the Textual form:

- shows the exact transition successor-note text;
- leaves the new rationale editor blank;
- preserves exact submitted wording;
- lets existing 22A/34A no-op semantics reject exact textual reuse.

No model or UI layer generates the new rationale.

## Explicit durable locators

The 44C form starts with five blank path inputs:

1. prior endpoint edge source;
2. changed working-set source;
3. changed working-set-note source;
4. 33B transition source;
5. no-overwrite 34A root destination.

Receipt locations are visible context only. They are not copied into these fields and do not become path identity.

## Branch coexistence

44C deliberately differs from pre-transition 44A/44B staleness.

Before 44B persistence, the candidate/transition is bound to the exact mounted ordinary controller; a rollover invalidates an unsaved crossing.

After 44B persistence, the transition is its own durable historical relationship. A later old-basis 30A rollover does not erase or retarget it. The exact successful 44B result can still support 34A root creation.

```text
persisted 33B transition
!= mounted-session adoption

old-basis rollover after 33B
!= invalidation of the persisted transition
```

This permits explicit branch coexistence without chronology, branch-preference, or global-head authority.
