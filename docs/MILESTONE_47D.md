# Milestone 47D — explicit third changed-basis session adoption

Decision: **D238**  
Issue: **#197**

## Product boundary

47C / D237 establishes one exact first public-34B edge after the exact third changed-basis public-34A root.

47D adds only the already-demonstrated declaration/adoption boundary:

```text
exact successful 47C edge
+ explicit current edge source
+ explicit no-overwrite declaration destination
→ existing root-started sequence load
→ existing declaration persist/load
→ standard governed controller
→ explicit shell-local adoption
```

This is the first 47-series step that intentionally replaces the shell's active governed controller.

It still does **not** create 40A third-epoch fresh-process re-entry, a 40B restart overlay, or third-epoch launch provenance.

## Why declaration and adoption remain one boundary

44E / D222 establishes the first-root pattern and 46D / D231 establishes the second-root pattern: once the exact first post-root edge exists, opening its one-edge root-started sequence, persisting/reloading the declaration, constructing the standard governed controller, and explicitly adopting that controller are one demonstrated product action.

40A / D202 expects the same third-root-backed declared-segment shape, but only after freshly reconstructing the prior persisted 37C/37D continuation and every explicit locator in the third-basis region.

Splitting declaration from in-process adoption at 47D would manufacture a new product boundary unsupported by prior implementation evidence.

## Prior art / reuse

47D reuses:

- 44E / D222 first-root declaration/adoption;
- 46D / D231 exact second-root declaration/adoption analogue;
- existing root-started sequence load;
- existing declaration persistence;
- existing declaration load/reconciliation;
- standard `ChromiumResearchSessionController`;
- 40A's established third-root declared-segment shape;
- the existing second-epoch authority inspection panel's immutable-launch / mutable-current projection.

40A is not an end-to-end substitute for 47D. It begins from a persisted prior second-epoch continuation overlay and freshly reconstructs all explicit third-basis locators before loading the declaration. It cannot consume the exact in-process 47C object and cannot explicitly promote that exact result into the current shell.

40B is restart configuration after an earned 40A result, not local adoption.

**No end-to-end substitute demonstrated in this review.**

## Application authority

`ChromiumResearchThirdChangedBasisSessionAdoptionResult` retains:

- exact `ChromiumResearchThirdChangedBasisRootEdgeResult`;
- freshly loaded one-edge third-root-started sequence;
- no-overwrite declaration persistence evidence;
- freshly reconciled declaration;
- standard governed controller.

`adopt_chromium_research_third_changed_basis_governed_session(...)` requires exactly the 47C result plus:

- explicit current 47C edge source;
- explicit no-overwrite declaration destination.

The exact third root is already loaded and retained by 47C. Only the explicit current edge file is reopened.

Before declaration, the application checks:

- retained third-root identity;
- retained 47C edge identity;
- exact third-root predecessor identity.

Fresh sequence/declaration/controller checks then prove:

- exactly one explicit edge;
- exact edge SHA;
- exact human endpoint wording;
- exact third-root starting predecessor;
- exact declaration SHA;
- exact governed endpoint edge.

## Explicit locator discipline

The adoption form begins with exactly two blank paths:

1. current first post-third-root edge source;
2. no-overwrite third-root-backed declaration destination.

The 47C edge path displayed in the candidate summary is audit receipt context only and is never prefilled.

No locator is inferred from:

- third-root receipt;
- third transition or changed working-set/note receipts;
- prior persisted 37C/37D overlay;
- raw 38F handoff context;
- second-epoch checkpoint paths;
- filenames/directories;
- hashes;
- chronology;
- current/latest/head or branch preference.

## Promotion semantics

Before explicit adoption, the mounted second-epoch continuation remains the shell's active governed state.

Declaration construction is checked while that exact controller/session/current typed continuation remains mounted.

Only after the exact adoption result is returned does promotion:

- replace `research_controller` with the exact adopted controller;
- replace session/presentation/working-set contexts from that controller;
- clear ordinary `research_reentry`;
- clear live changed-basis candidate authority that belonged to the old controller;
- clear pending ordinary restart/rollover receipts;
- remove historical second-epoch continuation/cumulative checkpoint controls and receipts;
- retain completed 47A–47D objects and receipts as historical evidence;
- retain `second_basis_epoch_continuation_reentry` only as ancestry/launch context.

A later rollover therefore uses the ordinary governed-session path. It cannot manufacture second-epoch checkpoint authority from historical ancestry.

## Inspection behavior

Inspectable persisted 37C/37D and raw 38F 47D products use the existing second-epoch inspection panel.

On adoption:

- immutable `launch_provenance` must remain the exact same object;
- persisted launch-location context remains unchanged;
- raw 38F launch location remains `None`;
- only current governed state advances from the exact adopted controller;
- persisted source wording identifies explicit 47D adoption;
- raw source wording identifies explicit 47D adoption after in-process 38F handoff.

On later ordinary rollover:

- immutable launch provenance remains unchanged;
- current state advances again from the visible ordinary continuation;
- no third-epoch launch path is invented.

No inspection schema change is required.

## Textual event ownership

The 47D handler owns only:

`adopt-research-third-changed-basis-session`

It does **not** manually call parent `on_button_pressed`. Inherited 47A/47B/47C and second-epoch actions remain Textual MRO-dispatched.

The application workflow method explicitly invokes inherited 47C persistence exactly once before mounting the adoption form. Event redispatch and workflow composition remain distinct.

## Falsification coverage

Focused tests cover:

- exact 47C result type;
- exact 47C edge object identity retained;
- exactly one root-started edge above the exact loaded third root;
- declaration fresh-relink identity;
- adopted controller endpoint identity;
- moved edge accepted only through caller-explicit current path;
- wrong edge locator rejected before declaration success;
- existing declaration destination preserved under no-overwrite failure;
- adoption controls absent before 47C and blank after exact success;
- explicit promotion replaces active controller;
- prior second-epoch typed continuation retained only as ancestry context;
- live changed-basis candidate authority cleared;
- second-epoch checkpoint widgets removed;
- post-adoption rollover uses ordinary governed-session behavior;
- persisted launch provenance unchanged while current state advances;
- raw 38F launch provenance unchanged and pathless while current state advances;
- plain 47C product scope isolation;
- factory authority-family rejection.

## Non-goals

47D does **not** add:

- 40A third-epoch fresh-process re-entry;
- 40B third-epoch restart overlay;
- third-epoch checkpoint or handoff;
- third-epoch launch provenance;
- a fourth evidence basis;
- generic Nth-root/Nth-adoption/Nth-epoch abstractions;
- a new persistence format;
- a new inspection schema;
- CLI locators;
- discovery or path prefill;
- current/latest/head/chronology/branch-ranking authority;
- path identity;
- trusted-time/authorship/authenticity claims;
- semantic-support or citation authority;
- browser reacquisition;
- autonomous research.

## Next boundary

If 47D is demonstrated, the next question is fresh-process verification: whether the exact adopted third-root-backed governed state can be proven through the existing 40A reconstruction boundary using newly explicit persisted locators, analogous to 46E after 46D.

That remains separate from 47D. No 40A result or 40B overlay is created here.
